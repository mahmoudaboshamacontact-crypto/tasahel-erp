# تساهيل ERP — قواعد الشغل

سيستم "تساهيل | قسم الخدمات الحكومية": HTML/JS/CSS عادي (RTL، عربي مصري) + Supabase + Vercel، بدون build وبدون framework. الرد لمحمود دايماً بالعربي المصري وبشرح بسيط. Claude بيراجع شغلك بعدك.

## قبل ما تبدأ
اقرأ `claude/STATUS.md` لو موجود (حالة المراحل والمقفول)، وحدّد في 3 سطور: إحنا في أنهي مرحلة، وإيه المطلوب بالظبط.

## تسليم الشغل
1. كل جزء على فرع جديد من main. ممنوع تعدّل على main أو تدمج. محمود هو اللي بيدمج.
2. ملف JS جديد لكل فيتشر (`js/NN-اسم.js`، الرقم اللي بعد آخر ملف موجود). ممنوع لصق كود كبير في ملف قديم.
3. في `index.html`: تضيف `<script ... defer>` الجديد في آخر القايمة بس. ممنوع تشيل أو تغيّر أي `<link>` أو `<script>` موجود، وأهمهم `css/tailwind.css`.
4. في `sw.js` تغيّر رقم CACHE بس.
5. SQL في ملف جديد داخل `sql/` بس، وبيتشغّل يدوياً من محمود.
6. قبل التسليم: `node --check` على كل JS، وتأكد إن مفيش أخطاء Console حمرا.
7. التقرير بالعربي: اسم الفرع، الملفات الجديدة/المعدّلة، ملفات SQL وبتعمل إيه، السطور المضافة في index.html، نتيجة الفحص، وأي حاجة مش متأكد منها.

## ممنوعات
- شاشة الدخول (`#login` في index.html ودوال الدخول في js/02 و js/03).
- المقفول: الاستردادات، js/41 و43 و44 و45 و46 و47 و48 و50، الأمان والـ RLS الموجود، HR والمناديب والكاش والنسخ الاحتياطي واسأل السيستم.
- واجهات تغطي نماذج موجودة، أو تنسخ بيانات من/إلى نماذج مخفية، أو تخفي رسائل الأخطاء.
- كود 3D أو أنيميشن دايم.
- مراقبة شخصية للموظفين (شاشة، ماوس، وجه، موقع دائم).

## قواعد تقنية
- بدون أنيميشن دايم. الحسابات من `allRequestLines`. لا تحديث تلقائي أسرع من 60 ثانية. الـ AI بياخد أرقام مجمّعة بس بدون أسماء أو تليفونات. ثيم برتقالي (`--r-*`). مقارنة الموظف بنفسه مش بزملائه.
- Tailwind ملف مبني مسبقاً (`css/tailwind.css`). أي كلاس مش موجود فيه اكتبه في CSS خاص بالفيتشر.
- تاب جديد للمدير: اتبع نمط `js/50-trash-archive.js` (لف switchTab و loadInitialData و handleLogout، زر في مجموعة admin في nav-menu). الدور من `window.__role`.
- الباقة مجانية: صف واحد لكل موظف في اليوم بدل سجلات كتيرة، وحمّل الحاجات التقيلة عند فتح التاب بس.

## قواعد Supabase / SQL
- idempotent (`create if not exists` / `drop policy if exists` / `or replace`).
- RLS شغال على كل جدول جديد. استخدم `(select auth.uid())`.
- ممنوع `security definer` من غير `set search_path = public`. والدوال الحساسة تتحقق من `public.is_manager()` وترمي exception.
- سياسات `allow_select_*` على request_lines و tx_comments و tasks بتخفي أي صف `deleted_at` فيه قيمة. ممنوع تغيّرها. `staff_only` و `no_partner_all` من نوع RESTRICTIVE.
- أي دالة عامة (بدون تسجيل دخول) تتبني في ملف SQL منفصل وماتنشرهاش قبل مراجعة Claude.

## قواعد أمان إضافية
1. الفلوس (مصاريف، مدفوعات منفذين، مطابقة محافظ، هامش ربح): select للمدير فقط.
2. أي حد أو سقف (زي سقف الخصم 20%) يتفرض في السيرفر بـ trigger أو RPC، مش في الـ JS بس.
3. دوال القرارات (اعتماد/رفض/تأكيد) تشتغل على `pending` فقط وترمي exception لو القرار اتاخد قبل كده، وتحدد البند بـ id.
4. التعديل الجماعي: ارفض القيم الفاضية والبنود غير المكتملة، ومتكتبش فوق سجل قديم إلا للمدير.
5. جداول الملاحظات: تعديل المحتوى للمؤلف أو المدير فقط.
6. الدوال العامة (anon): كود عشوائي 8 خانات على الأقل (رقم TX-سنة-4 أرقام قابل للتخمين)، حد محاولات لكل معاملة وحد عام مع `pg_advisory_xact_lock`، لا كتابة على النجاح، ترجع حالة فقط، والمطابقة بـ `exists`.
7. الـ JS: `escapeHtml` على كل نص قبل innerHTML، `select` بأعمدة محددة و`limit`، ولا تسحب request_lines/audit_log كاملين.

## لو مش متأكد
اسأل محمود سؤال واحد قصير. ما تخمّنش في أرقام الفلوس أو الصلاحيات.
